# dsh-model-meta-fill

中文 | [English](<./README.en.md>)

DeepSeek Harness（DSH）的模型元数据填入插件。在「设置 → 模型」中，为 `llm-pi-ai` 下显式配置的本地模型匹配 [models.dev](https://models.dev) 的模型资料，经逐模型、逐字段差异预览确认后，补齐或覆盖上下文窗口、最大输出 token 数、输入类型和思考等级四项配置。

手动维护中转站、自定义网关或第三方渠道的模型列表时，通常要逐个查资料再手填参数，思考等级对应的接口值尤其容易配错。本插件在供应商卡片上提供「自动填入」和「覆盖填入」入口，只改动这四项元数据：不会修改本地模型的原始请求 ID，也不会向客户端暴露供应商密钥或自定义请求头。

## 核心特点

### 双目录关联，区分模型本体与服务记录

插件同时拉取 `models.dev/models.json`（模型本体目录）和 `models.dev/api.json`（各供应商的服务记录目录），只通过完全一致的 `canonical_model_id` 建立关联。

搜索和匹配本地模型时只面对去重后的模型本体，不会被同一模型在多个托管平台的重复记录干扰；需要思考控制等服务级参数时，再读取关联的服务记录。自动推断来源时，上下文窗口、最大输出 token 数和输入类型取自模型本体，思考等级取自选中的服务记录；手动指定服务来源后，四项配置全部取自所选服务记录，不混入其他来源的数据。

### 保守匹配，不改写原始请求 ID

匹配本地模型时依次检查完整 ID、名称归一化（统一大小写、空白、下划线、连字符与 Unicode NFKC）、网关路径后缀和显示名称，保留版本号、日期以及 `pro`、`mini`、`thinking` 等区分模型身份的片段，避免跨版本或跨变体误配。

带冒号后缀的模型 ID 不会自动截断成匹配结果，仅在完整匹配失败后作为候选列出，必须由用户确认。同时命中多个模型本体时也会交由用户选择，不会默认取第一条。无论自动匹配还是人工映射，都只用来查找资料，本地模型实际发请求用的原始 ID 始终不变。

### 自动推断来源，两类人工关系独立维护

刷新目录时，插件从模型本体 ID 提取研发方前缀，按供应商 ID 的完整匹配（`exact`）或最长左侧完整词前缀（`prefix`）推断默认服务来源；按名称无法归属研发方的渠道（`none`，如第三方托管或异名渠道）不会自动选中。

自动规则不适用时，可以在「关系管理」中分别维护两类人工映射：

- 模型映射：本地供应商 + 原始模型 ID → 模型本体 ID
- 来源映射：模型本体 ID → 供应商 ID + 服务模型 ID（对匹配到同一本体的所有本地模型共用）

两类映射独立保存、独立移除，刷新目录会保留人工映射。如果目标消失或失去关联，插件会将关系标记为失效。该模型需要修正关系或使用自定义参数才能继续填入。

### 关键设计决策

**自定义参数优先。** 自定义参数按原始模型 ID 精确匹配，区分大小写和路径前缀。不同供应商的同 ID 模型共用一套参数。命中后直接以保存的四项参数为来源，跳过模型本体和服务来源映射。这样目录未收录的模型也能填入，同一条关系也能用于多家供应商。

新增时可以从某条本地模型的当前映射结果复制一份模板，包含已保存的人工模型映射和来源映射。也可以直接输入原始模型 ID，手动填写。上下文窗口、最大输出 token 数和输入类型缺项时留空。模板未提供推理等级时，开关默认关闭。保存的是一份独立配置，后续目录刷新或映射更新都可以继续使用这份配置。

### 补缺失与覆盖分离，先预览差异再确认

供应商卡片提供两个独立入口：「自动填入」只补未声明的缺失字段，保留本地已有合法配置（包括显式声明的仅文本 `["text"]` 和明确关闭思考的 `false`）；「覆盖填入」用所选来源的明确有效值替换已有字段，来源缺少的字段仍保留本地值，不会清空。

两个入口都会先打开「填入预览」，逐模型、逐字段列出当前值、填入值、具体资料来源以及跳过或警告原因。有歧义的模型可以直接在预览里做一次性选择，不必先保存映射。

预览生成后会锁定本次使用的资料快照和配置修订号，确认填入使用 30 分钟内单次有效的 token。如果在确认前人工关系或本地模型配置发生变动，提交会被拒绝，必须重新查看差异后再确认。

### 字段边界明确，不推测思考等级

输入类型按本地模型实际保存的声明判断是否缺失，不以界面默认勾选状态为准；只写入 DSH 支持的 `text` 和 `image`，忽略 PDF 与音视频，也不写入空数组。

思考等级只映射服务记录中明确列出的 `effort` 枚举（`off / minimal / low / medium / high / xhigh / max`，其中 `none` 映射为 `off` 并保留接口值 `none`），或在服务明确声明 `reasoning: false` 时写入 `false`。仅提供布尔开关、token 预算或 `default` 等无对应关系的记录，会在界面展示原始说明并提示原因，不自行补造档位；对 `google-generative-ai` 协议还会额外校验，仅在等级全部属于同名四档（`minimal / low / medium / high`）时写入。本地已有无效字段时，「自动填入」会提示并跳过，不静默修改。

### 本地缓存容错与双语界面

远端目录缓存在本地存储域，启动时如无缓存或缓存超过 7 天会自动刷新，也可随时手动刷新；刷新失败时仍可继续使用已有完整缓存。

插件界面自带中英文文案，跟随 DSH 界面语言切换，且无需前端构建步骤。

## 安装

方式 1：在 DSH 的 Web profile 中从 npm 安装：

```sh
dsh plugin --profile web add dsh-model-meta-fill
```

方式 2：直接从 GitHub 安装：

```sh
dsh plugin --profile web add github:yuhhhong/dsh-model-meta-fill
```

方式 3：在 DSH 的插件页中，点击添加插件，填入 npm 包名：`dsh-model-meta-fill`

安装后重启 DSH 并刷新页面，打开「设置 → 模型」。已显式配置模型列表的供应商卡片上会出现「自动填入」和「覆盖填入」按钮，页面底部会显示「模型元数据填入」状态栏与「关系管理」入口。

如需卸载：

```sh
dsh plugin --profile web remove dsh-model-meta-fill
```

当前插件版本为 `0.2.0`，支持的 DSH 版本范围为 `>=0.2.2-rc.2 <0.3.0`。

## 使用说明

### 资料缓存与刷新

模型设置页底部的「模型元数据填入」区域显示缓存状态、最近更新时间和各类已保存关系的数量。点击「刷新资料」可从 `models.dev` 更新目录。已有缓存时，刷新失败会保留旧缓存。尚无缓存时，已保存自定义参数的模型仍可填入。

### 预览与确认填入

在已显式配置模型列表的供应商卡片上，点击「自动填入」或「覆盖填入」打开「填入预览」。窗口中按模型逐行显示匹配状态、来源状态、待改字段的「当前值 → 填入值」、资料来源（`models.json:<canonicalId>` 或 `api.json:["<provider>","<modelId>"]`）以及跳过或警告提示。

- 遇到多个候选或冒号后缀候选时，可以直接在该行的「仅本次选择」下拉框中选定模型本体，只更新当前预览，不保存关系；随时可点「清除本次选择」。
- 需要处理未匹配模型、失效关系或调整服务来源时，点击该行的「指定 / 管理关系」，会直接进入对应的映射表单。从预览进入模型映射表单且尚未保存映射时，也可以直接点「仅本次选择」。
- 核对差异无误后点击「确认填入」写入配置；点击「关闭」则不会改动任何模型配置。

### 关系管理

点击模型设置页底部的「关系管理」，在「模型映射」「来源映射」和「自定义参数」三个标签页查看已保存的关系。

- 表单里的本地模型、模型本体和服务记录选择器均支持在同一个输入框中搜索并选择。
- 在已保存的模型映射行上，可以直接点击「新增来源映射」或「编辑来源映射」，为该模型本体指定服务记录。
- 从填入预览进入并保存模型映射后，如果当前本体没有可用的自动来源且存在关联候选，界面会引导继续指定服务来源，也可以点「暂不指定」仅保留模型映射。
- 在「自定义参数」中可新增、编辑和移除整套参数。保存和移除只更新插件关系。移除后，下次填入恢复从映射取值，已经填入的值需要通过「覆盖填入」更新。
- 从预览跳转过来修改关系后，点「返回填入预览」会自动重算差异，仍需点击「确认填入」才会写入。

## 范围与限制

- 仅处理 `llm-pi-ai` 下已显式配置且非空的 `models` 列表，不为内置自动目录、DeepSeek 直连适配器或账号目录创建覆盖配置。
- 仅映射明确可转换的 `effort` 枚举；只有布尔开关或 token 预算的记录不推导等级，也不改动协议兼容参数或供应商预算配置。
- `models.dev` 的资料反映上游模型与服务描述，不能验证某个中转站或网关在实际调用时是否真正支持对应能力。
- 插件不在运行期间定期后台轮询刷新；长时间未重启 DSH 时，可在底部状态栏手动点击「刷新资料」。

## 本地开发

项目无安装脚本，也无前端打包构建步骤。Host 端直接声明 `@deepseek-ai/schemastery` 和 `zod` 运行时依赖，Client 端由 DSH 浏览器模块加载器直接运行源码。

安装依赖后可运行语法检查与单元测试：

```sh
npm ci
npm run check
npm test
```

如果通过 DSH 插件管理器以本地目录链接方式安装，请先在本项目目录运行 `npm ci`，再完全退出并重新打开 DSH 桌面端，确认插件已启用。

在 DSH 会话环境中，也可以用桌面端内置的 Node 运行时验证真实 JSON 存储的初始化与缓存重读（仅写入临时目录）：

```sh
ELECTRON_RUN_AS_NODE=1 "$DSH_NODE_EXECUTABLE" --test test/host.test.js
```
